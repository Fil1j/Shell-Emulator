# Эмулятор командной оболочки (прототип)

## 1. Общее описание

Консольное приложение (CLI), эмулирующее простую командную оболочку.
Оно написано на Python 3 с использованием только стандартной библиотеки
и оформлено по PEP 8.

Текущий этап (прототип) включает:

- интерактивный цикл чтения команд (REPL);
- приглашение к вводу, построенное из реальных данных ОС;
- парсер строки с поддержкой кавычек;
- сообщения об ошибках (неизвестная команда, неверные аргументы);
- команды-заглушки `ls` и `cd`, команду `exit`.

**Требования:** Python 3.8 или новее (тесты проверялись на 3.12).
Сторонние зависимости не нужны.

**Структура проекта:**

```text
.
├── .gitignore               # исключения для Git
├── Makefile                 # цели run, test, lint, clean
├── README.md                # документация
├── run.sh                   # запуск (Linux/macOS)
├── run.bat                  # запуск (Windows)
├── src/
│   └── shell_emulator.py    # исходный код эмулятора
└── tests/
    └── test_shell_emulator.py   # модульные тесты (unittest)
```

## 2. Описание функций и настроек

### Настройки

Конфигурационных файлов, переменных окружения и аргументов командной строки
нет. Приглашение формируется автоматически, а код возврата задаётся
командой `exit`.

### Приглашение к вводу

Формат: `username@hostname:path$ `

- `username`: имя пользователя ОС (`getpass.getuser()`);
- `hostname`: имя хоста (`socket.gethostname()`);
- `path`: текущий каталог (`os.getcwd()`). Домашний каталог заменяется
  на `~`.

Пример: `user@laptop:~/projects$ `

### Команды

| Команда         | Поведение                                                        |
|-----------------|------------------------------------------------------------------|
| `ls [арг...]`   | Заглушка. Выводит `ls: аргументы = [...]`.                       |
| `cd [арг...]`   | Заглушка. Выводит `cd: аргументы = [...]`. Каталог не меняется.  |
| `exit [код]`    | Завершает работу. Код возврата по умолчанию 0.                   |

Пустая строка игнорируется. Ctrl+D (конец ввода) завершает работу,
Ctrl+C отменяет текущую строку.

### Правила разбора аргументов

Строка разбирается по правилам POSIX-оболочки (`shlex.split`):

- аргументы разделяются пробелами;
- текст в одинарных `'...'` или двойных `"..."` кавычках передаётся
  как один аргумент, пробелы внутри сохраняются;
- обратный слеш `\` экранирует следующий символ;
- кавычки в результат не попадают.

### Ошибки

Сообщения об ошибках выводятся в stderr, работа эмулятора продолжается.

| Ситуация                      | Сообщение                                            |
|-------------------------------|------------------------------------------------------|
| Неизвестная команда           | `foo: команда не найдена`                            |
| Незакрытая кавычка            | `ошибка разбора: No closing quotation`               |
| `exit` с нечисловым аргументом| `exit: неверный аргумент: 'abc' (требуется целое число)` |
| `exit` с лишними аргументами  | `exit: слишком много аргументов`                     |

### Функции модуля `shell_emulator.py`

| Объект                | Описание                                                      |
|-----------------------|---------------------------------------------------------------|
| `ShellError`          | Исключение с сообщением, которое увидит пользователь.         |
| `get_prompt()`        | Возвращает строку приглашения.                                |
| `parse_line(line)`    | Разбирает строку в список токенов. При ошибке кавычек вызывает `ShellError`. |
| `cmd_ls(args)`        | Реализация заглушки `ls`.                                     |
| `cmd_cd(args)`        | Реализация заглушки `cd`.                                     |
| `cmd_exit(args)`      | Проверяет аргументы и вызывает `sys.exit(code)`.              |
| `print_stub(name, args)` | Печатает имя команды и аргументы.                          |
| `COMMANDS`            | Словарь «имя команды → обработчик». Новые команды добавляются здесь. |
| `execute(tokens)`     | Находит обработчик и выполняет его, иначе вызывает `ShellError`. |
| `main()`              | Главный цикл чтения и выполнения команд.                      |

## 3. Сборка и тесты

### Сборка

Отдельная сборка не требуется: проект состоит из одного Python-файла.
Достаточно получить код:

```bash
git clone <адрес-репозитория>
cd <каталог-проекта>
```

### Запуск

```bash
./run.sh              # Linux/macOS
run.bat               # Windows
make run              # через Makefile
python3 src/shell_emulator.py   # напрямую
```

### Тесты

Тесты написаны на стандартном `unittest`, установка пакетов не нужна:

```bash
make test
```

Эквивалентная команда без `make`:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v      # Linux/macOS
set PYTHONPATH=src && python -m unittest discover -s tests -v  # Windows (cmd)
```

### Проверка стиля PEP 8 (необязательно)

```bash
pip install pycodestyle
make lint
```

### Очистка

```bash
make clean            # удаляет каталоги __pycache__
```

## 4. Примеры использования

Сеанс работы (`$ ` в начале строк пользовательского ввода):

```text
$ ./run.sh
user@laptop:~$ ls
ls: аргументы = []
user@laptop:~$ ls -la /tmp
ls: аргументы = ['-la', '/tmp']
user@laptop:~$ ls "My Documents" 'a b' plain
ls: аргументы = ['My Documents', 'a b', 'plain']
user@laptop:~$ cd "/home/user/my dir"
cd: аргументы = ['/home/user/my dir']
user@laptop:~$ cd
cd: аргументы = []
```

Обработка ошибок:

```text
user@laptop:~$ foo bar
foo: команда не найдена
user@laptop:~$ echo "unclosed
ошибка разбора: No closing quotation
user@laptop:~$ exit abc
exit: неверный аргумент: 'abc' (требуется целое число)
user@laptop:~$ exit 1 2
exit: слишком много аргументов
```

Завершение работы и проверка кода возврата:

```text
user@laptop:~$ exit 3
$ echo $?
3
```

Неинтерактивный запуск (команды из файла или канала):

```bash
printf 'ls "a b" c\nexit 0\n' | ./run.sh
```
